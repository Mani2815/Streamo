# Streamo v1.0.0 — Initial Stable Release

Streamo is a complete, real-time API-to-Analytics Data Engineering Platform. This initial stable release focuses on delivering a robust, locally reproducible data pipeline that spans from ingestion to observability.

## Highlights

- **Real-time API ingestion**: A resilient polling service that handles external API backoffs and failures natively.
- **Kafka event streaming**: Durable message buffering to decouple ingestion from processing.
- **Spark processing**: Event-time processing, watermark-based deduplication, and window aggregations using Apache Spark Structured Streaming.
- **PostgreSQL persistence**: A fast SQL serving layer populated via idempotent JDBC upserts.
- **MinIO object storage**: A locally hosted S3-compatible data lake storing raw, processed, and quarantined Parquet files.
- **Data quality monitoring**: Automated quarantine of malformed JSON payloads, null values, and out-of-range sensor data to an isolated MinIO bucket.
- **Analytics dashboard**: A FastAPI and Vanilla JS frontend providing a polished interface for viewing data quality, source metrics, and real-time trends.
- **Airflow orchestration**: Scheduled background tasks that guarantee data freshness, monitor quality SLA rates, and prune historical Postgres records.
- **Grafana monitoring**: Pre-provisioned dashboards for infrastructure observability and pipeline health tracking.
- **Docker Compose deployment**: A reproducible local development and execution environment.
- **AWS EC2 deployment**: Streamo is fully deployable to AWS EC2 using the existing Docker Compose architecture.

## Deployment

### Local Docker Compose
Streamo is built to be run locally. By running `docker compose up -d`, the entire stack including databases, message brokers, spark workers, and monitoring tools will spin up connected over a single Docker network.

### AWS EC2 Deployment
Streamo has been successfully deployed and tested on AWS EC2. Due to the high memory footprint of running Kafka, Spark, Postgres, MinIO, and Airflow simultaneously, a sufficiently sized EC2 instance (e.g., `t3.xlarge` or larger) is required.

## Known Limitations

- **Cloud Hosting Uptime**: The AWS EC2 deployment may be stopped when not in active use to avoid unnecessary cloud infrastructure costs. It is not guaranteed to be permanently available 24/7.
- **Local Memory Requirements**: Running the full stack locally via Docker Desktop requires significant memory. A minimum of 8GB of RAM allocated to Docker is recommended; 16GB is ideal to prevent Out-Of-Memory (OOM) errors during Spark execution.
- **External API Constraints**: The mock API operates smoothly, but hooking into third-party real-world APIs will be subject to their individual rate limits and availability.
- **University AWS Account Dependency**: Cloud deployments are subject to any restrictions or budget caps placed on the underlying AWS educational/university account.
- **Single-Node Execution**: While Kafka and Spark are distributed systems, the current Docker Compose deployment runs them as single-node instances to optimize for local development and reproducibility.
